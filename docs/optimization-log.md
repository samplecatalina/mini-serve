# Optimization log

Each entry records what was expected before a change was measured, what was measured, and why the two differ. Performance numbers link to rows under `results/` or reports under `profiling/`; correctness findings link to tests.

## M0 — Environment, reference model, correctness anchor

M0 has no performance changes. The entries below are the findings that shaped the test infrastructure every later change is judged by.

| Hypothesis | Prediction | Measured | Difference | Evidence |
|---|---|---|---|---|
| A FlashInfer op in the environment check exercises the runtime JIT toolchain (nvcc + host compiler), the path that breaks on cluster nodes with an incompatible host compiler. | An `rmsnorm` smoke test compiles through nvcc and leaves a built `.so` in the FlashInfer cache. | The test passed, but the JIT log was empty and no `.so` was produced: in flashinfer 0.6.7 `rmsnorm` defaults to CuTe DSL kernels compiled in-process. | The check verified numerics but not the toolchain. Switched to single-request decode attention (Qwen3 GQA shape), which is built by ninja + nvcc; the check now requires a JIT-built `.so`. Its `build.ninja` contains only `-gencode=arch=compute_89,code=sm_89`, no `-march`. | `miniserve/tools/env_check.py` (`check_flashinfer_jit`) |
| FlashInfer's cache location is controlled by `FLASHINFER_CACHE_DIR`. | Setting it redirects JIT artifacts out of `$HOME`. | flashinfer 0.6.7 reads only `FLASHINFER_WORKSPACE_BASE` (`flashinfer/jit/env.py`); artifacts land under `$FLASHINFER_WORKSPACE_BASE/.cache/flashinfer/<version>/<arch>/`. | Variable renamed in the image; the environment check asserts every cache directory resolves outside `$HOME`. | `Dockerfile`, `check_cache_dirs` |
| A plain-PyTorch Qwen3 that mirrors the transformers op order reproduces HF exactly. | Greedy tokens identical to HF; prefill logits bitwise equal. | 6 prompts, 1128 generated tokens (one 512-token run) identical; prefill logits over 563 positions bitwise equal (max abs diff 0.0). | None. | `tests/test_consistency.py` |
| Incremental decoding (prefill + one token per step) gives the same logits as one forward pass over the full sequence. | Bitwise equal, since the math is identical. | Max abs logit difference 0.34 over 32 steps; argmax flipped at one position where the top two logits (14.938 vs 14.875) were one BF16 ulp apart. HF shows the same flip between its full forward and `generate`. | Different GEMM shapes accumulate in different orders. The test bounds the difference (< 1.0) and requires equal argmax only where the top-2 gap exceeds 0.25. Consequence for batching: changing the batch dimension can flip near-tied tokens, which motivates the tolerance policy in `docs/design.md`. | `test_incremental_decode_matches_full_forward` |
| Token equality is a sufficient correctness anchor. | Any injected bug in the forward path changes greedy output. | Offsetting RoPE positions by one diverged at token 12. Setting one layer's `q_norm` weight to ones left 64 greedy tokens unchanged while shifting logits by up to 1.875. | Token equality misses small errors. The reference path therefore asserts bitwise prefill logits, which catches the `q_norm` mutation. | `test_prefill_logits_match_hf` |
